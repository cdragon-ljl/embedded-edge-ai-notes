# Roofline 性能模型：一眼看出算子卡在算力还是带宽

> 系列：CUDA 高性能算子实战 · NPU-12
> 前置：NPU-05（矩阵乘法优化）、NPU-07（Nsight Compute 分析）
> 配套环境：Python 3.10+、pip install numpy matplotlib（绘图代码不需要 GPU）

## 0. 本节目标

前七节我们一直在"优化某个算子"：tiling、共享内存、归约、Shuffle。但有一个更根本的问题还没系统回答：**一个算子到底有没有优化空间？瓶颈是计算还是访存？** 如果方向错了——比如一个访存密集算子你花两周优化计算指令——收益可能趋近于零。

本节引入高性能计算最经典的分析工具 **Roofline 模型**：

1. 用两个硬件参数（峰值算力、峰值带宽）画出一条"性能天花板"；
2. 用"算术强度"把任意算子放到这张图上，**一眼定位它是计算受限还是访存受限**；
3. 给出可运行的 Python 代码，为你的 5060 Ti 画出专属 Roofline，并用它指导优化决策。

这个模型的价值在于**跨硬件通用**：单片机、GPU、NPU 都能用同一套逻辑分析。它也是算子开发岗位面试的高频考点。

## 1. 两个硬件参数与一个算子参数

### 1.1 峰值算力（Compute Peak）

**定义 1（峰值算力, Peak FLOPS）**：硬件每秒最多能完成的浮点运算次数，单位 FLOP/s。它由核心数、主频、每周期指令数决定：

```
峰值算力 ≈ 核心数 × 主频 × 每周期浮点次数
```

对 RTX 5060 Ti（sm_120）：4608 个 CUDA 核心 × 约 2.5 GHz × 2（FMA 一次算乘加）= 约 **24 TFLOPS**（FP32）。注意这只是 FP32 的理论值；FP16 用 Tensor Core 可以到 100+ TFLOPS，INT8 更高——精度越低，峰值算力越高。

### 1.2 峰值带宽（Memory Peak）

**定义 2（峰值带宽, Peak Bandwidth）**：硬件每秒最多能从内存/显存搬运的字节数，单位 Byte/s。RTX 5060 Ti 的显存带宽约 **448 GB/s**（GDDR7，128-bit 位宽）。

嵌入式直觉：MCU 的"算力"是内核运算速度，而"带宽"是总线/Flash/DMA 的搬运速度。一个 72 MHz 的 MCU 上，如果数据要从 SPI Flash 慢慢读进来，你优化 ALU 指令再快也没用——瓶颈在搬运。GPU 上完全同理。

### 1.3 算术强度（Arithmetic Intensity）

**定义 3（算术强度, AI）**：一个计算任务中，**每搬运 1 字节数据平均能做多少次浮点运算**：

```
算术强度 AI = 总浮点运算量（FLOP） / 总数据搬运量（Byte）
```

- AI 高 → 计算密集（算得多、搬得少）→ 瓶颈在算力；
- AI 低 → 访存密集（搬得多、算得少）→ 瓶颈在带宽。

嵌入式类比：AI 就像"算力/搬运比"。SPI Flash 读取一个 512 字节扇区，如果只做 10 次运算，AI 极低，典型访存密集；如果把这 512 字节读进 SRAM 做 FFT（上千次运算），AI 就高多了。

## 2. Roofline 图：性能天花板

### 2.1 两条约束线

把"可达性能"画成算术强度的函数，Roofline 由两条线组成：

1. **带宽限制线**（斜线）：性能上限 = AI × 峰值带宽。斜率就是带宽——数据搬得快，性能才能高。
2. **算力限制线**（水平线）：性能上限 = 峰值算力，AI 再高也超不过这条线。

两条线的交点叫 **拐点（Ridge Point）**：

```
拐点 AI = 峰值算力 / 峰值带宽
```

5060 Ti FP32：`24e12 / 448e9 ≈ 53.6 FLOP/Byte`。意思是：算子的 AI 低于 53.6 时，被带宽卡住；高于 53.6 时，被算力卡住。

### 2.2 用 5060 Ti 参数画出专属 Roofline

```python
import numpy as np
import matplotlib.pyplot as plt

# RTX 5060 Ti 参数（FP32；以 deviceQuery/NVIDIA 官网为准）
peak_flops = 24e12      # 峰值算力 24 TFLOPS
peak_bw    = 448e9      # 峰值带宽 448 GB/s
ridge = peak_flops / peak_bw   # 拐点 ≈ 53.6 FLOP/Byte

# 算术强度横轴（对数范围）
ai = np.logspace(-2, 3, 300)

# 两条约束：可达性能 = min(带宽限制, 算力限制)
bandwidth_bound = ai * peak_bw
compute_bound   = np.full_like(ai, peak_flops)
roofline = np.minimum(bandwidth_bound, compute_bound)

plt.figure(figsize=(9, 6))
plt.loglog(ai, roofline, 'b-', linewidth=2.5, label='Roofline (FP32)')
plt.axvline(ridge, color='r', ls='--', alpha=0.7,
            label=f'Ridge Point ≈ {ridge:.1f} FLOP/B')

# 标注两个典型算子（数值见 3.2 节）
ai_add   = 1 / 12.0                 # 向量加法
ai_gemm  = 1024 / 6.0               # GEMM N=1024
plt.plot(ai_add, ai_add * peak_bw, 'go', markersize=11,
         label='向量加法 (访存密集)')
plt.plot(ai_gemm, peak_flops, 'ro', markersize=11,
         label='GEMM N=1024 (计算密集)')

plt.xlabel('算术强度 (FLOP/Byte)')
plt.ylabel('可达性能 (FLOPS)')
plt.title('RTX 5060 Ti Roofline 模型（FP32）')
plt.legend()
plt.grid(True, which='both', alpha=0.3)
plt.tight_layout()
plt.savefig('roofline_5060ti.png', dpi=150)
print("拐点 =", round(ridge, 1), "FLOP/Byte")
```

运行后会生成 `roofline_5060ti.png`。这张图就是你的"优化决策地图"。

## 3. 典型算子的算术强度分析

### 3.1 向量加法：典型的访存密集

对 N 个元素的向量加法 `C = A + B`：

- 运算量：每元素 1 次加法 → `N` FLOP；
- 搬运量：读 A（4N 字节）+ 读 B（4N 字节）+ 写 C（4N 字节）= `12N` 字节；
- 算术强度：`AI = N / 12N = 1/12 ≈ 0.083 FLOP/Byte`。

对照 5060 Ti 的 Roofline：0.083 远小于拐点 53.6，处于**带宽限制区**。理论可达性能上限 = `0.083 × 448e9 ≈ 37 GFLOPS`——而峰值算力是 24 TFLOPS，**利用率不到 0.2%**。

结论：向量加法再怎么写也快不了，它的天花板就是带宽。优化的正确姿势是减少搬运（比如融合相邻算子、用向量化加载），而不是优化计算指令。

### 3.2 矩阵乘法：计算密集的代表

对 `N×N×N` 的 GEMM（`C = A×B`）：

- 运算量：`2N³` FLOP（乘加各一次）；
- 搬运量（理想情况下）：读 A（4N²）+ 读 B（4N²）+ 写 C（4N²）= `12N²` 字节；
- 算术强度：`AI = 2N³ / 12N² = N/6`。

当 `N = 1024`：`AI ≈ 170`，**大于拐点 53.6**，处于计算限制区——理论上能达到峰值算力。这就是为什么 GEMM 是"优化甜点"：计算密集、有大量 tiling 空间，优化收益立竿见影。

当 `N = 64`：`AI ≈ 10.7`，小于拐点，变成访存密集。这就是为什么小矩阵 GEMM 很难优化到峰值——数据还没搬完就算完了。

### 3.3 常见算子速查

| 算子 | 算术强度（约） | 限制类型 | 优化方向 |
|:---|:---|:---|:---|
| 向量加法 / 逐元素 | 0.08 | 带宽 | 融合、减少中间张量 |
| Softmax | ~0.1~0.3 | 带宽 | 分块 + 在线归一化（省读两遍） |
| 卷积（小核） | 中低 | 带宽为主 | im2col/隐式 GEMM + tiling |
| GEMM（N≥512） | N/6 ≥ 85 | 计算 | Tensor Core、寄存器级 tiling |
| GEMM（小 N） | N/6 < 53 | 带宽 | 减少切块开销、批量 GEMM |

判断方法就一条：**把算子的 AI 和拐点比一比**，小于拐点=带宽受限，大于拐点=计算受限。

## 4. Roofline 怎么指导优化决策

### 4.1 决策规则

| 情况 | 结论 | 优化手段 |
|:---|:---|:---|
| 实际性能远低于带宽线 | 访存没用好 | 增大访存连续度、向量化、共享内存/缓存复用 |
| 实际性能贴在带宽线上 | 已是带宽极限 | 只能减少搬运（算子融合、量化降精度） |
| 实际性能远低于算力线 | 计算没用好 | tiling 减少访存等待、提高占用率、用 Tensor Core |
| 实际性能贴在算力线上 | 已是计算极限 | 只能减少计算量（算法级优化）或换更高精度硬件 |

嵌入式类比：这就像 MCU 上分析瓶颈——`stm32` 上做 DMA 搬运的代码，你优化循环里的一两条指令毫无意义；反过来，一个 FFT 循环如果卡在算力，你优化 DMA 配置也没用。**先定位瓶颈类型，再选优化手段。**

### 4.2 结合 Nsight Compute 实测

Roofline 是"理论上限"，实际性能要用 Nsight Compute（前面学的 `ncu`）测出来，然后把实测点画到 Roofline 图上：

- 实测点离 Roofline 线越远，说明优化空间越大；
- 点贴在线上，说明已经到极限，再优化只能换方向（融合/量化）。

```bash
ncu --metrics gpu__time_duration.sum,sm__throughput.avg.pct_of_peak_sustained_elapsed,gpu__compute_memory_throughput.avg.pct_of_peak_sustained_elapsed ./your_kernel
```

`sm__throughput` 接近 100% 而 `compute_memory_throughput` 低 → 计算受限；反过来 → 访存受限。两个指标一起看，就完成了"Roofline 理论 → 实测验证"的闭环。

## 6. 小结

Roofline 模型用两个硬件参数画出一条性能天花板，用算术强度把任意算子定位到图上：

- **带宽限制**：AI 低于拐点，性能上限 = AI × 带宽，优化方向是减少搬运；
- **计算限制**：AI 高于拐点，性能上限 = 峰值算力，优化方向是减少计算/用更快的计算单元；
- **拐点 = 峰值算力 / 峰值带宽**，是判断"访存密集 vs 计算密集"的分界线。

这套方法论与硬件无关——MCU、GPU、NPU 通用。Roofline 的结论也直接指向了下一步的优化手段：当多个带宽受限的算子连在一起时，最有效的优化是**算子融合**——把中间张量的写读省掉，把"多个访存密集"变成"一个访存密集"。这正是 kernel 设计里的核心手法。
